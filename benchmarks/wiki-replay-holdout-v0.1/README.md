# Wiki 下一题留出集 v0.1

项目自拟 12 条合成样本，编写时参考了开发试点暴露的问题，未复用原 JD、题面或回答。按检索、会话记忆、工具调用分为三个主题。每个主题含一条具体回答、一条含糊回答、一条未确认经历和一条来源冲突。此集供当前逻辑一次性验收。用其中的错误修改项目后，该批样本只能作为后续回归集。

`cases.jsonl` 只描述候选输入。`oracles.jsonl` 分别记录固定脚本应走的路径和人工比较的考点。两份文件按字节冻结。回放时不会把 oracle 发送给面试官。

## 本地免费复跑

在仓库根目录使用项目 Python，选择新输出目录。

```powershell
$env:PYTHONPATH='backend/src'
python -m interview_agent.evaluation.wiki_replay --suite benchmarks/wiki-replay-holdout-v0.1 --out .private/wiki-holdout-scripted
python scripts/check-live-wiki-replay.py --suite holdout --mode mock --out .private/wiki-holdout-sdk
```

第一条运行 A/B/C 的固定脚本回放。第二条使用专用测试 PostgreSQL 与 Redis，走实际 API、Worker、SDK 和账本。SDK 响应由本地 MockTransport 生成。本轮的 SDK 对照固定为 B/C，B 带共同题源和标记，C 额外带一条合格 Wiki。样本只用于测出题决策。实际的发布、撤回和访问控制使用其已有的产品集成证据核对。

## 题面审核

1. 先只看生成的盲审表。逐题判断是否贴合岗位、承接回答、难度匹配、尊重引用和事实边界。记录 X/Y 的差别再选择胜者。查看原始轨迹和映射后再核对原因。
2. 回答具体时，追问应推进一个可验证的技术细节，或在已覆盖后合理换题。回答含糊时，优先用一个贴题的场景澄清边界。同一条 Wiki 题有可能因为缺少前置理解而跨度过大，也可能提供恰当的具体例子。
3. 没有可比较的合格题记作无效，只有两道都合格且相近才记平。若一侧有错误前提、虚构经历、泄露答案或来源问题，单独记为边界问题。保留每条理由和失效样本。
4. 解盲后按 W1 原线统计：固定 6 条可追问样本，C 至少 4 胜且胜多于负，实际题面至少改变一次，另 6 条边界样本没有规定的约束退化。无效不计胜，分母仍为 6。只有实模题面加独立审核才能给出这项结论。程序的读取与采用记录用来定位变化，不能替代评审。

当前仅用于新样本的协议和模拟检查；合成资料标记及合成 JD 未验证真实岗位分布。
