# 后续开发路线

项目已具备本地面试、题库、材料与复盘的完整主流程。实习投递期间优先完善能通过面试反馈检验的部分，每一轮保留复现入口与可读结果。

| 顺序 | 方向 | 完成判据 |
| --- | --- | --- |
| 1 | 面试题质量与引文 | 扩大真实题面盲评，覆盖多个 JD、可读和不可读的搜索输入。对齐正文块、准备阶段的来源取舍和首题引用，记录贴岗程度、深度及原文关系。 |
| 2 | 产品体验 | 完善简历材料到开场的路径，减少手动配置，清楚显示等待和失败。为首次体验补充短演示与预设合成岗位。 |
| 3 | 安装与复现 | 将 Windows 构建参数改为从开发环境配置获取。在干净环境验证首次启动、升级、回退和数据库备份。 |
| 4 | 稳定性与成本 | 给准备、材料和面试 Worker 补故障恢复测试、上下文大小回归和成本统计。 |
| 5 | 服务部署 | 根据实际使用反馈评估远程部署、账号管理和运维需求。 |

收到面试反馈后，先保存所对应的岗位要求、触发条件和实际输出。可复现的失效样例进入评测，依据同一批样例决定是否合并改动。
